# Gioco v3 "Turno di notte" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rifare il gioco in `/gioco/` come un giro di 10–15 minuti in un edificio low poly e liminale che mostra tutti i progetti di oakvx, con le finestre usate in ogni ala, musica liminale che si distorce ai cambi di stanza e una stanza personale riempibile da JSON.

**Architecture:** Si tiene il motore v2 (Three.js r187, fisica AABB scritta a mano, `Mondo`, `Portali`, stanze come moduli ES). Si aggiungono: varchi fissi non euclidei (`engine/passaggi.js`), musica generativa (`musica.js`), effetti sonori, nuovi materiali, e un livello di logica pura in `js/logica/` senza Three.js, testato con `node --test`. Le stanze v2 di trama si cancellano; i transiti liminali v2 si riusano.

**Tech Stack:** JavaScript ES modules senza bundler, Three.js r187 (vendor), Web Audio API, `node:test` per l'unità, Playwright preinstallato per i test nel browser (solo in locale).

**Spec:** `docs/superpowers/specs/2026-11-26-gioco-v3-design.md`

## Global Constraints

- Nessun bundler, nessuna dipendenza nuova; solo `gioco/vendor/three/` (r187). Ogni `.js` deve passare `node --check` (lo fa `scripts/check_site.py`).
- I moduli in `gioco/js/logica/` non importano Three.js né toccano il DOM: girano sotto `node --test`.
- Tutti i testi IT/EN in `gioco/contenuti.json` o `gioco/dati/narratore.json`; il nome usato nei testi è **oakvx** (mai "Gabri").
- Colori delle finestre: ciano `#39c6d9`, magenta `#d95bb3`. Mai arancio/blu, mai nomi/loghi/personaggi/armi/livelli di Half-Life, Portal o Backrooms.
- Giro principale 10–15 minuti; ogni stanza-progetto è obbligatoria; indizio a **45 s** senza progresso, soluzione visibile a **90 s**; timer fermi in pausa.
- Nessun link esterno nel gioco tranne la schermata finale (mailto, copia email, torna al sito, rigioca).
- "Calmo" e `prefers-reduced-motion`: niente ondeggiamento, distorsione musicale dimezzata e senza calo di intonazione.
- Contatore commit: API ricerca commit GitHub per `oakvx` e `oakvxish`, cache 1 h in `localStorage` (chiave `gioco-commit-v1`), ripiego `2.500+`.
- Stanza di oakvx riempita solo da `gioco/dati/stanza-oakvx.json` e file in `gioco/oakvx/`; file mancanti o JSON rotto non rompono il gioco.
- Al massimo 2 varchi fissi resi per fotogramma, più la coppia di finestre del giocatore.
- Commit: `git config user.name oakvx`, `git config user.email oakvx7@gmail.com`, messaggi senza righe di attribuzione, branch `gioco-v3`.

## Review Focus

- Giocatore incastrato o caduto dopo un varco (finestra in un angolo, salto nel pozzo di Piko): deve tornare al punto di controllo della stanza attuale, non all'ingresso. → test in Task 3.
- GitHub offline, 403 o limite superato: il muro dei commit mostra `2.500+` senza errori in console. → test in Task 19.
- `stanza-oakvx.json` malformato, brani o immagini 404: la stanza si costruisce lo stesso, gli elementi rotti si saltano. → test in Task 20.
- Audio spento o `AudioContext` bloccato dal browser: il gioco si gioca, nessuna eccezione, le piattaforme di Brat seguono un orologio anche senza audio. → test in Task 7 e Task 12.
- Cambio lingua a metà partita: cartelli, didascalie, monitor e terminale si ridisegnano nella nuova lingua. → test in Task 8.
