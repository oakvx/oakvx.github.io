The project

Beautify manages customers, appointments, users and services across multiple salons. It includes public booking, inventory and analytics, with separate sections for owners and employees.

How it works

A salon and its users

After login, the session identifies the active salon. Users can belong to multiple salons; owner and employee roles determine which sections they can access.

Finding a time

The public booking flow selects a salon, service and date. PHP logic calculates slots using duration, opening windows and staff capacity.

Shared checks between the agenda and public booking compare occupied time intervals. The supplied version proposes slots every 30 minutes and applies a minimum lead time of 15 minutes.

Managing data

The PHP backend uses mysqli for customers, services, appointments and settings. Queries include the active salon to separate each business’s data.

The CRM includes customer history, inventory and analytics. The database also contains user-to-salon associations and account recovery tables.

My work

I developed the PHP backend and MySQL database, including CRUD workflows, salon context and shared availability checks for the agenda and public booking.

PHP, server side

The backend handles the CRM’s application workflows. My work includes creating, reading, updating and deleting data.

MySQL, data side

The schema links salons, customers, services and appointments, with associations between users and salons. Queries include the active salon.
