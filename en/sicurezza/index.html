07Security

(07) SecurityWhat I actually do, what I don't promise

Security isn't a badge. It's a list of choices.

Here are mine, project by project. And, further down, what I won't promise.

(i) This site

I start with my own.

01

Nobody follows you

No analytics, no tracking cookies, no ads. Fonts are served from here, not from someone else.

02

Few outside calls

External requests go only to GitHub's public API (commits, repos, languages) and Open-Meteo (Sassuolo's weather, not yours). No keys, nothing about you is sent.

03

Little in your browser

Your language, whether you paused the animations, a cached copy of the counters and, in the Warehouse, fake chips and games in progress. Nothing that identifies you, nothing that leaves the browser.

04

Every version stays

The code is public on GitHub and every change is a commit: anything can be checked and rolled back.

I

piko

Nothing without permission

Actions only in apps granted for the session, after an approved plan. Password and credential windows refused. An API reachable only from the same computer, behind a token.

II

yag

Secrets stay on the host

The browser sees the gateway key, never the upstream ones. Revocable client keys with scopes, enforced size and connection limits, malformed requests rejected.

III

synk

Data at the salon, backups encrypted

PostgreSQL on a local PC, ports only on 127.0.0.1, CSRF-protected sessions in the dashboard, encrypted backups, privacy requests tracked without chat content.

IV

middleManPS4

Metadata, nothing else

The network tools record DNS, TCP and TLS metadata only: no decryption, no credential capture. Writers never overwrite existing files.

(ii) What I don't promise

I'd rather say it first.

  • 01

    Nothing is 100% secure

    Anyone who promises it is selling something. I reduce risks and write down the ones left.

  • 02

    Experimental means experimental

    yag has no native TLS and shouldn't sit on an untrusted network; synk is a release candidate not meant for real client data yet. Their READMEs say so up front.

  • 03

    One backup is not a backup

    Copies need to live in more than one place, and someone has to try restoring them.
